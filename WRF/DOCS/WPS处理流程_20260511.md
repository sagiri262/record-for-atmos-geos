# 1、`namelist.wps` 需要改哪些变量？三层嵌套用 `max_dom=3` 还是 `ndown.exe`？

## 我的建议

你说“跑完 d01 后跑 d02 再接着 d03”，这句话有两种含义：

| 目的                                                    | 推荐方案                  |
| ----------------------------------------------------- | --------------------- |
| 三个域一起跑，d01/d02/d03 同时积分，最简单                           | `max_dom = 3`         |
| 严格先跑 d01，再用 d01 的 `wrfout` 给 d02 做边界，再用 d02 给 d03 做边界 | `ndown.exe`           |
| 第一次跑通 ERA5 + WRF-Chem                                 | 优先 `max_dom = 3`，先少踩坑 |
| 省算力、只关心最内层、严格单向离线嵌套                                   | `ndown.exe`           |

WRF 官方用户指南里，在线嵌套是多个不同分辨率的域同时运行；父域给子域边界，子域也可以反馈给父域。关键嵌套变量包括 `max_dom`、`parent_id`、`i_parent_start`、`j_parent_start`、`parent_grid_ratio`、`parent_time_step_ratio` 等。([无效重定向][2])
`ndown.exe` 是离线单向嵌套：先做粗网格运行，再用 `ndown.exe` 把粗网格输出转换为细网格的初始和边界条件；三层及以上也能做，但官方文档也说流程比较繁琐，需要严格按文件名规则操作。([无效重定向][2])

## `namelist.wps` 三层嵌套核心变量

WPS 三大程序是 `geogrid.exe`、`ungrib.exe`、`metgrid.exe`；`geogrid` 定义网格并插值静态地理数据，`ungrib` 解 GRIB 气象数据，`metgrid` 把气象数据水平插值到 WRF 网格。([无效重定向][1])

你三层嵌套时，`namelist.wps` 重点改这些：

```fortran
&share
 wrf_core = 'ARW',
 max_dom = 3,
 start_date = '2025-04-09_08:00:00','2025-04-09_08:00:00','2025-04-09_08:00:00',
 end_date   = '2025-04-16_08:00:00','2025-04-16_08:00:00','2025-04-16_08:00:00',
 interval_seconds = 3600,
 io_form_geogrid = 2,
/

&geogrid
 parent_id         = 1, 1, 2,
 parent_grid_ratio = 1, 3, 3,
 i_parent_start    = 1, XX, YY,
 j_parent_start    = 1, XX, YY,
 e_we              = D01_WE, D02_WE, D03_WE,
 e_sn              = D01_SN, D02_SN, D03_SN,
 geog_data_res     = 'default','default','default',
 dx = 27000,
 dy = 27000,
 map_proj = 'lambert',
 ref_lat   = 42.5,
 ref_lon   = 115.0,
 truelat1  = 30.0,
 truelat2  = 60.0,
 stand_lon = 115.0,
 geog_data_path = '/path/to/WPS_GEOG/'
/

&ungrib
 out_format = 'WPS',
 prefix = 'FILE',
/

&metgrid
 fg_name = 'SFILE','FILE',
 constants_name = 'ERA5_INVARIANT',
 io_form_metgrid = 2,
/
```

这里 `DX/DY/ref_lat/ref_lon/truelat/stand_lon/e_we/e_sn/i_parent_start/j_parent_start` 需要按你的实际 d01、d02、d03 范围确定，不能只由 `AREA=[60,90,25,140]` 自动推出。WPS 文档说明，区域域中心由 `ref_lat/ref_lon` 定义，粗域尺寸由 `dx/dy/e_we/e_sn` 定义；嵌套域的分辨率由 `parent_grid_ratio` 递推得到。([无效重定向][1])

特别注意：嵌套域的 `e_we` 和 `e_sn` 必须满足：

```text
e_we = n * parent_grid_ratio + 1
e_sn = n * parent_grid_ratio + 1
```

例如 `parent_grid_ratio=3` 时，`e_we/e_sn` 应该是 `100, 121, 151, 181, 202...` 这种 “3 的倍数 + 1”。这是为了让嵌套域右上角和父域格点对齐。([无效重定向][1])

# 2、使用 ERA5 跑数据的 WPS 流程

ERA5 是小时再分析资料，ECMWF 说明 ERA5 提供大量大气、陆面和海洋变量的小时估计，常用 CDS 版本为规则经纬网 0.25°；ERA5 数据可用 single levels 和 pressure levels。([ECMWF][3])
CDS 可以网页下载，也可以用 CDS API 下载；官方知识库说明两种方式都支持，API 请求里也可指定 `data_format='grib'`。([confluence.ecmwf.int][4])

## 下载时建议

你这段时间是 2025-04-09 08 UTC 到 2025-04-16 08 UTC。若用小时 ERA5，下载时要包含：

```text
2025-04-09: 08:00 到 23:00
2025-04-10 到 2025-04-15: 00:00 到 23:00
2025-04-16: 00:00 到 08:00
```

`namelist.wps` 里：

```fortran
interval_seconds = 3600
```

如果你只下载 3 小时或 6 小时间隔，`interval_seconds` 就分别改成 `10800` 或 `21600`，并保证所有时次文件齐全。

## ERA5 变量

最基本的 WRF 输入需要三维气压层变量和二维地面变量。WRF 官方教程列出的必需字段包括：三维温度、U/V 风、位势高度、相对湿度；二维地面气压、海平面气压、SST/skin temperature、2 m 温湿、10 m 风、土壤温湿和土壤高度等。([无效重定向][5])

ERA5 通常分两类下载：

```text
ERA5/PRESSURE/  # pressure levels
ERA5/SURFACE/   # single levels
```

WRF 论坛的 ERA5 指南也建议把 Copernicus CDS 的 ERA5 pressure levels 和 single-level surface data 分开下载、分开 ungrib，之后在 metgrid 里一起读入。([WRF & MPAS-A Support Forum][6])

## 基本流程

```bash
cd WRF/run   # 或 test/em_real

./real.exe
```

WRF 官方文档说明，真实个例必须先成功跑完 WPS，并把 `met_em.*` 链接或复制到 WRF 运行目录；之后编辑 `namelist.input` 的 `&time_control` 和 `&domains`。([无效重定向][2])
嵌套运行中，`real.exe` 成功后会生成粗域和嵌套域的 `wrfinput`，以及粗域边界文件 `wrfbdy_d01`；随后运行 `wrf.exe`，成功后生成各个域的 `wrfout`。([无效重定向][2])

## `namelist.input` 时间部分

你的模拟长度是 7 天：

```fortran
&time_control
 run_days                            = 7,
 run_hours                           = 0,
 run_minutes                         = 0,
 run_seconds                         = 0,

 start_year                          = 2025, 2025, 2025,
 start_month                         = 04,   04,   04,
 start_day                           = 09,   09,   09,
 start_hour                          = 08,   08,   08,

 end_year                            = 2025, 2025, 2025,
 end_month                           = 04,   04,   04,
 end_day                             = 16,   16,   16,
 end_hour                            = 08,   08,   08,

 interval_seconds                    = 3600,

 input_from_file                     = .true., .true., .true.,
 history_interval                    = 60, 60, 60,
 frames_per_outfile                  = 24, 24, 24,

 io_form_input                       = 2,
 io_form_history                     = 2,
 io_form_restart                     = 2,
 io_form_boundary                    = 2,
/
```

WRF 文档说明，`run_days/run_hours` 可控制积分长度，且会优先于结束时间；`interval_seconds` 是 real-data 输入资料的时间间隔，也是边界条件文件的时间间隔。([无效重定向][2])

## `namelist.input` 网格部分

这里的 `e_we/e_sn/i_parent_start/j_parent_start/parent_grid_ratio` 必须和 `namelist.wps` 对应：

```fortran
&domains
 time_step                           = 162,   ! 例：d01=27 km，则 6*27=162 s，WRF-Chem 常需更保守

 max_dom                             = 3,

 e_we                                = D01_WE, D02_WE, D03_WE,
 e_sn                                = D01_SN, D02_SN, D03_SN,
 e_vert                              = 45, 45, 45,

 p_top_requested                     = 5000,

 num_metgrid_levels                  = 按 met_em 文件实际值填写,
 num_metgrid_soil_levels             = 4,

 dx                                  = 27000, 9000, 3000,
 dy                                  = 27000, 9000, 3000,

 grid_id                             = 1, 2, 3,
 parent_id                           = 1, 1, 2,
 i_parent_start                      = 1, XX, YY,
 j_parent_start                      = 1, XX, YY,
 parent_grid_ratio                   = 1, 3, 3,
 parent_time_step_ratio              = 1, 3, 3,

 feedback                            = 0,
 smooth_option                       = 0,
/
```

`time_step` 一般先按 `6 × dx(km)` 估算，WRF 文档也给出“典型个例不超过 `6*dx(km)`”的经验规则；WRF-Chem 因为化学变量多、CFL 更敏感，通常要更保守。([无效重定向][2])

`num_metgrid_levels` 不要猜，建议这样查：

```bash
ncdump -h met_em.d01.2025-04-09_08:00:00.nc | grep NUM_METGRID_LEVELS
ncdump -h met_em.d01.2025-04-09_08:00:00.nc | grep NUM_METGRID_SOIL_LEVELS
```

三层嵌套时通常这样：

```fortran

 specified                           = .true.,  .false., .false.,

```

这一块没有唯一标准，要看研究区、分辨率和研究目标。一般至少要检查：

```fortran

 ra_lw_physics                       = 4, 4, 4,
 ra_sw_physics                       = 4, 4, 4,

 sf_sfclay_physics                   = 1, 1, 1,
 sf_surface_physics                  = 2, 2, 2,
```

经验上，若 d03 是 3 km 左右，通常关闭 d03 积云参数化，即 `cu_physics = ..., 0`；d01/d02 是否开启看分辨率。`num_land_cat` 要和 `geo_em/met_em` 的土地利用类别匹配。

# 4、加入 WRF-Chem 模块后，WRF 怎么跑？

WRF-Chem 不是只改一个开关。它至少多了三件事：

1. 编译时启用化学模块。
2. 选择化学机制和气溶胶机制。
3. 为每个域准备化学初始/边界条件、排放清单文件。

WRF-Chem 用户指南说明，WRF-Chem 已作为 WRF 模型包的一部分发布，但它依赖基本 WRF 设置，建议先熟悉普通 WRF 的编译、配置和运行再做 WRF-Chem。([etrp.wmo.int][8])

## 编译 WRF-Chem

```bash
cd WRF

export WRF_CHEM=1
# 使用 KPP 机制时才需要：
export WRF_KPP=1

./configure
./compile em_real >& compile.log
```

WRF-Chem 指南说明，`WRF_CHEM=1` 是把 chemistry code 编进 WRF 的必需环境变量，并且配置和编译时都需要；某些 KPP 化学机制还需要 `WRF_KPP=1`。指南还特别提示，WRF-Chem 不支持 shared-memory OpenMP 选项，实际案例建议用 distributed memory 方式。([etrp.wmo.int][8])

编译成功后应有：

```text
main/real.exe
main/wrf.exe
main/ndown.exe
```

WRF-Chem 指南也说明，成功编译后应能在 `main` 目录看到 `ndown.exe`、`real.exe`、`wrf.exe`。([etrp.wmo.int][8])

## WPS 阶段不因 WRF-Chem 大改

WPS 仍然是：

```bash
geogrid.exe
ungrib.exe
metgrid.exe
```

区别是后面 `real.exe` 和 `wrf.exe` 的 `namelist.input` 要加 `&chem`，并且排放工具通常需要 `wrfinput_d0*` 作为网格模板。

## `namelist.input` 加入化学设置

最关键的是 `&chem`。`chem_opt=0` 表示不启用化学，非零值决定具体化学机制和气溶胶模块；WRF-Chem 指南列出大量 `chem_opt` 选项，并说明这部分是化学 namelist 的核心。([etrp.wmo.int][8])

示意：

```fortran
&chem
 chem_opt                            = 选择的机制, 选择的机制, 选择的机制,

 chem_in_opt                         = 1, 1, 1,

 io_style_emissions                  = 2,
 emiss_opt                           = 取决于排放清单和化学机制,
 emiss_inpt_opt                      = 取决于排放物种映射,

 bio_emiss_opt                       = 0 或 1/3,
 dust_opt                            = 0 或相应选项,
 seas_opt                            = 0 或相应选项,

 gas_drydep_opt                      = 1, 1, 1,
 aer_drydep_opt                      = 1, 1, 1,

 phot_opt                            = 1, 1, 1,
 photdt                              = 30, 30, 30,
 chemdt                              = 2.0, 0.6667, 0.3333,

 kemit                               = 排放文件垂直层数,
/
```

WRF-Chem 指南说明，`io_style_emissions=0/1/2` 分别表示不读排放、两个 12 小时排放文件、日期时间特定排放文件；`emiss_opt`、`bio_emiss_opt`、`emiss_inpt_opt` 等要与化学机制和排放清单匹配。([etrp.wmo.int][8])
多域 WRF-Chem 时，很多化学 namelist 变量也要按域给数组值，用户指南给出的多域示例就是 `chem_opt = 301, 301`、`chemdt = 2.0, 0.66666`、`emiss_opt = 5, 5` 这类写法。([etrp.wmo.int][8])

## 化学输入文件要准备什么

至少检查这些文件是否齐全：

```text
wrfinput_d01
wrfinput_d02
wrfinput_d03
wrfbdy_d01

wrfchemi_d01_*
wrfchemi_d02_*
wrfchemi_d03_*

化学初始/边界条件文件或被 mozbc 修改过的 wrfinput/wrfbdy
```

WRF-Chem 用户指南说明，运行带化学和不带化学的主要差别之一，是需要额外的数据集描述化学物种来源；很多排放文件必须由用户针对自己的区域和化学机制外部准备。
NCAR/ACOM 的 WRF-Chem 工具页列出常用预处理工具：`mozbc` 用于从全球化学模式输出创建化学初始和侧边界条件，`anthro_emiss` 用于从全球排放清单生成 WRF-Chem 的人为排放文件，`fire_emiss` 用于火点排放，`bio_emiss` 用于 MEGAN 生物源排放。([www2.acom.ucar.edu][9])

典型 WRF-Chem 顺序是：

```bash
# 1. WPS 已完成，met_em.d0* 已有
ln -sf /path/to/WPS/met_em.d0* .

# 2. namelist.input 已加入 &chem，并选好 chem_opt/emiss_opt 等
./real.exe

# 3. 生成或链接排放文件
#    例如 wrfchemi_d01_*, wrfchemi_d02_*, wrfchemi_d03_*

# 4. 生成/写入化学初始和边界条件
#    例如使用 mozbc 修改 wrfinput_d0* 和 wrfbdy_d01

# 5. 跑 WRF-Chem
mpirun -np N ./wrf.exe
```

WRF-Chem 指南里的流程也明确提到：先运行 `real.exe` 生成包含化学变量的 `wrfinput`，确认排放文件在运行目录并按需要命名，然后运行 `wrf.exe`。([etrp.wmo.int][8])

## WRF-Chem 下 `max_dom=3` 和 `ndown.exe` 的选择

对你这个需求，我会这样定：

```text
普通 WRF 测试：先 max_dom=3 跑通
WRF-Chem 第一次测试：仍建议 max_dom=3，feedback=0，三域同时跑
后续正式长时间模拟：再考虑 ndown.exe 单向离线嵌套
```

原因是 WRF-Chem 已经多了化学初始场、化学边界场、排放物种映射、每个域排放文件、化学机制匹配等问题。`ndown.exe` 对三层域本身就繁琐，三层 WRF-Chem 再叠加化学物种边界会更容易出错。先用 `max_dom=3` 验证 ERA5→WPS→real→wrf.exe 和排放读入是最稳的路线。

最后的最小可执行路线是：

```text
ERA5 下载：pressure + surface + invariant
WPS：geogrid → ungrib pressure → ungrib surface → metgrid
WRF 普通：real.exe → wrf.exe
WRF-Chem：重新编译 WRF_CHEM=1 → real.exe → 排放/mozbc → wrf.exe
嵌套策略：先 max_dom=3；确定要离线逐级跑时再上 ndown.exe
```
